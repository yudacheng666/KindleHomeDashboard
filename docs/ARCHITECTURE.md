# 架构（独立后端方向已确认）
## 已确认方向
用户选择独立轻量后端 + 按需 HA 对接。现有 NAS 优先，核心通勤、天气和显示不依赖 HA；不重复建设智能家居平台。不以 AI 开发量为选型依据。具体实现和布局仍待验证。
## 候选实现
一个独立容器，内部模块化采集、时间调度、校验/限额/退避/缓存、家庭业务、灰度渲染和专用手机管理网页。持久目录独立，JSON 或 SQLite 按需求选择。HA 官方 API 按需提供智能家居及获准复用的待办，家庭数据保持单一权威来源。使用资源限制、退出重启、独立版本及回退；应用级超时与恢复必需，容器健康检查不等于自动恢复卡死。仍共享 NAS、网络与外部服务；测试对原 HA 的实际影响。默认不启用额外硬件、付费服务、常驻浏览器或复杂更新平台。
## 数据层与验收
供应商适配逻辑与显示和调度解耦；统一线路/方向、真实多车 ETA、源时间/最新成功采集时间、无车/停运/错误/过期等语义。分时采集、限额、超时、退避、去重、有效期、变化触发及本地离线提示。先确认合法免费额度、覆盖及真实接口响应，再开展业务开发。用公开无关示例做接口连通性探测；真实私有配置仅在获准的本地环境验证，公开 CI 不含秘密或家庭配置。实测端到端新鲜度、故障恢复、请求量、CPU/RAM/存储、HA 服务影响、手机体验与真机显示。
## 取舍
HA 具备成熟原生功能、统一 App/备份及较低额外进程开销，但集成共享运行环境和版本生命周期。独立方案提供专用体验、供应商适配自由度及故障隔离；并不自动增加数据授权或免费额度。真实稳定性与资源开销仍需实测。HA 作为整体后端的候选不再推进，相关集成只保留可复用的参考。
