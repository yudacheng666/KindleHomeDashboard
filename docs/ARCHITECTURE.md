# 架构（独立后端方向已确认）
## 已确认方向
用户选择独立轻量后端 + 按需 HA 对接。现有 NAS 优先，核心通勤、天气和显示不依赖 HA；不重复建设智能家居平台。不以 AI 开发量为选型依据。具体实现和布局仍待验证。
## 分模块交付
先共享最小基础服务、公交与家庭功能，分别启用、测试、上线；驾车延后，不让地图密钥或出图阻塞首批。天气可独立追加，顺序待确认。保持单容器、模块开关、数据卷独立和向后兼容的配置迁移，避免每个模块独立常驻服务。家庭生活统一待办、海报、菜单及购物清单，共用本地存储、管理入口和展示调度；结构化本地文本配置、灰度渲染，内容不变不反复刷屏；公交高频采集与海报轮播/屏幕刷新解耦，不能因换页而阻断采集。优先复用手机管理服务。不引入外部图床或存储私人原图。
### 家庭生活展示候选（待确认）
默认今日总览聚合未完成今日待办、当前有效重点提醒、当日相关餐次；全屏大字海报、今日菜单进入低频轮播，本周菜单/购物清单默认手动查看、可加入轮播；没有内容的页面跳过，全部为空显示简洁空状态。任务与海报是不同内容类型，同一任务可映射为海报而不重复录入，海报浏览不改变任务完成状态；购物条目来自用户确认的食材及手动条目，菜单变化不默默删除手动条目或覆盖已完成状态。候选优先级：手动固定/设置 > 当前有效的用户明确置顶提醒 > 通勤时段公交 > 家庭普通轮播；非紧急提醒不抢占公交，过期/完成项自动离开活跃轮播（仅关联任务的海报随任务状态），夜间默认静态。手动取消固定后恢复当前时段策略；轮播候选每页2–5分钟，可配置；手机修改后仅必要画面刷新；时间/切页不触发额外上游采集。优先使用单一 NAS 存储与调度，不增加常驻服务；全部规则/默认值须预览确认和真机验证。
## 候选实现
一个独立容器，内部模块化采集、时间调度、校验/限额/退避/缓存、家庭业务、灰度渲染和专用手机管理网页。持久目录独立，JSON 或 SQLite 按需求选择。HA 官方 API 按需提供智能家居及获准复用的待办，家庭数据保持单一权威来源。使用资源限制、退出重启、独立版本及回退；应用级超时与恢复必需，容器健康检查不等于自动恢复卡死。仍共享 NAS、网络与外部服务；测试对原 HA 的实际影响。默认不启用额外硬件、付费服务、常驻浏览器或复杂更新平台。
## 数据层与验收
供应商适配逻辑与显示和调度解耦；统一线路/方向、真实多车 ETA、源时间/最新成功采集时间、无车/停运/错误/过期等语义。分时采集、限额、超时、退避、去重、有效期、变化触发及本地离线提示。公交配置使用 NAS 单一权威数据：线路搜索 /traffic/v2/querytrafficline、方向详情 /traffic/v1/querybusline、站序及 ID 校验，上车站查询 ETA；Kindle 与手机共用局域网配置服务，明确保存后切换采集目标并清除旧站缓存，配置写入需授权、防误触。Kindle 简单网页表单或轻量触摸客户端待型号固件实测，不因增加选站而引入常驻浏览器服务；旧设备浏览器兼容与 FBInk 输入/渲染分别验证。现有免密钥公交接口按用户决定可暂用于原型，保留可替换适配器、低频退避及明确风险，不绕过限制。其余接口按正规授权、免费额度及真实响应验收；未通过不冒充正式可用。驾车候选：同一供应商的多路线算路 API 与官方静态地图，NAS 按需生成显示帧，优先不使用常驻浏览器；保留版权标识，核查静态图片使用、灰度处理、URL长度/点数与额度限制，不能将未返回的路线伪造为备选。手机端可按需使用同供应商地图组件。实际地图出图与墨水屏可读性待验证。用公开无关示例做接口连通性探测；真实私有配置仅在获准的本地环境验证，公开 CI 不含秘密或家庭配置。实测端到端新鲜度、故障恢复、请求量、CPU/RAM/存储、HA 服务影响、手机体验与真机显示。
## 取舍
HA 具备成熟原生功能、统一 App/备份及较低额外进程开销，但集成共享运行环境和版本生命周期。独立方案提供专用体验、供应商适配自由度及故障隔离；并不自动增加数据授权或免费额度。真实稳定性与资源开销仍需实测。HA 作为整体后端的候选不再推进，相关集成只保留可复用的参考。
## 家庭访问（已确认简化方向）
手机、Kindle直接访问可信家庭局域网NAS，不配对、不要求查看凭证。可明确启用免密码管理或选择HTTPS管理凭证；原本机鉴权模式保留。不增设认证常驻服务、不开放公网或访客网络。实际地址、网段和防火墙参数仅本地配置；NAS Docker源地址与实际设备兼容性待验证。
