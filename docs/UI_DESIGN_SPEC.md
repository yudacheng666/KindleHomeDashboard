# UI 设计规范候选（2026-11-26）

状态：调研完成后的设计候选，尚未经用户批准为实施规范；未修改业务代码、配置、接口、权限或发布版本。基线 main 4e576db95f6ae8b3d47d890c1d93c2e1f17a482a，v0.1.0-rc.18。本文负责视觉、组件、交互、响应式和验收规则；OVERVIEW_LAYOUT.md 负责总览内容组织候选，两者分工，本文不批准改变地图数量/位置、默认页面、自动分时、天气/海报轮播或已有模块能力。

## 调研依据与取舍
- [TRMNL Framework 3.4](https://trmnl.com/framework/docs/3.4/)（[Value](https://trmnl.com/framework/docs/3.4/value/)、[Layout](https://trmnl.com/framework/docs/3.4/layout/)、[Responsive](https://trmnl.com/framework/docs/3.4/responsive)、[Runtime](https://trmnl.com/framework/docs/3.4/framework_runtime/)）：专用 ePaper 设计体系；借鉴语义化数值、标题、标签、间距、区域布局及按屏幕密度适配，不直接引入现代 CSS/JS 运行时到旧 Kindle，不照抄固定画布的像素字号。
- [Microchip ePaper Display Fundamentals](https://developerhelp.microchip.com/xwiki/bin/view/software-tools/mgs/dev-kits/epd-ug/fundamentals/)：高对比、静动分区、减少重绘、无动画、局部更新及残影清理；实际面板控制器决定刷新能力，不将其他硬件的固定刷新周期套用 Kindle。
- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)：网页可访问性基准，目标 AA（未做完整合规审计）。1.4.3 正常文本至少4.5:1、大文本3:1；1.4.11 必要非文本边界/图形3:1；1.4.1 不仅用颜色；1.4.4 文本放大200%；1.4.10 320 CSS px重排（必要二维图表例外）；1.4.12 用户改变文本间距不损失内容；2.1.1 键盘；2.4.7/2.4.11 焦点可见且不被遮盖；2.5.8 AA目标24×24 CSS px或满足例外；2.5.5 AAA目标44×44 CSS px或满足例外；2.5.7 拖动操作有单指非拖动替代；2.2.2 非必要自动更新提供暂停/停止/隐藏或频率控制；3.3.1/3.3.2 错误与标签；4.1.3 状态消息。不是所有 AA 指标均可由 CSS 尺寸保证。
- [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：常规命中区域44×44 pt，动作与状态一致。
- [Android Touch target size](https://support.google.com/accessibility/android/answer/7101858)、[Material adaptive layouts](https://developer.android.com/develop/ui/views/layout/canonical-layouts)、[window size classes](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)：48×48 dp 推荐，列表/详情及辅助面板适配窗口。pt、dp、CSS px 不等价；本项目手机另选48 CSS px目标。
- [Ant Design 布局](https://ant.design/docs/spec/layout-cn/)、[亲密性](https://ant.design/docs/spec/proximity-cn/)、[字体](https://ant.design/docs/spec/font-cn/)：8px节奏、信息分组、桌面14/22字号行高；不引入整个企业组件库。
- [GOV.UK 布局](https://design-system.service.gov.uk/styles/layout/)、[错误消息](https://design-system.service.gov.uk/components/error-message/)、[错误摘要](https://design-system.service.gov.uk/components/error-summary/)、[USWDS Form](https://designsystem.digital.gov/components/form/)：移动优先单列、字段标签、就地错误+可跳转摘要、保留输入。
- [W3C 中文排版需求](https://www.w3.org/TR/clreq/)（工作组说明文档，非合规认证）：中文标点、混排、换行；[NN/g 十项可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)：状态可见、贴近用户语言、防错、一致性、识别优于记忆。
- 上述规则系外部参考与本地候选的组合，不宣称某个第三方标准规定本项目具体字号/边距或已达到认证。

## Kindle 展示
- 不越狱：以实际浏览器可用视口为基准，宽度填满、取消固定最大宽度及空白占位；ES5/XHR、普通块/表格式 CSS，渐进增强，JS能力验证优于仅UA推断。浏览器工具栏/休眠/硬件刷新不可由网页保证控制。不要禁止缩放，不用假全屏或固定100vh裁切。
- 越狱：同一数据与内容结构，全屏能力仅在已核实型号/固件及获准安装后验证；轻量原生/FBInk客户端可作为候选，真机验证局部刷新、残影、退出恢复及重启。不得假设 DOM 局部修改等于硬件局刷；不默认增加 NAS 常驻浏览器或第二套业务服务。
- 模块共享标题、关键值、状态、时效、数据来源、分隔线组件；高密度表格/数字行代替大圆角嵌套卡片；固定关键数字区域，仅变化字段更新，长内容自然滚动或明确分页，摘要注明还有N项且保留完整入口。
- 模块规则：公交最近/后续两车同列对齐且第一辆更突出，计划发车不当作ETA，过期不伪装实时；天气地点平等且现有120秒轮播、保留现有六项与预警/来源；驾车三目的地及真实返回的各自多条路线保留，地图编号/线型在实机验证且不擅自变换供应商图片、隐去归因，地图布局另行确认；待办按日期分组、仅有权限且当期/逾期可二次确认完成；菜单按日期/餐次、今日低调标注、原展示范围；海报大字且完整信息可达，独立轮播设置保留。不得为密度削掉已批准能力。
- 核心信息优先、预警完整可达；轮播暂停入口集中设置；预览不等于最终布局批准。展示与采集频率/请求预算独立；非必要动态减少，实际刷新参数由硬件验证决定。

## 手机/电脑后台
- 手机采用任务导向的单列列表→独立详情/编辑；桌面可采用左侧约200–240px导航+主内容+按需预览。候选断点小于600单列、600–1023按空间选择两栏、1024以上导航+内容；按窗口而非设备型号，320px也须可操作，浏览器返回保留模块和合理滚动位置。保留旧入口及权限行为；仅设计候选，不新增账号。
- 同类组件统一：整行点击的设置入口、主/次/危险动作、开关、分段选项、原生日期和时间选择、可搜索结果列表、状态消息、二次确认、空状态/加载/失败/无权限。用语义 button/label/input，键盘可达、明显焦点、读屏名称与状态；不靠悬停/颜色/滑动完成唯一操作。手指点击立即反馈（目标100ms内本地反馈，非承诺后端写入时间），禁用期间说明原因；防重复提交，不能无反馈吞点击；键盘弹出不遮挡输入或保存，固定底栏应有普通流式退路。
- 表单：标签在上，必要时简洁提示；常用字段先、坐标/额度等高级字段后，外传同意必须在相应请求前；具体字段错误+页首可定位摘要，失败不丢草稿，未保存离开提示，保存回执/必要回读确认后才显示成功。保存中、已保存、失败、结果未确认分开，失败允许明确核对后重试，不能盲目重放删除。
- 公交：线路搜索→方向→上车站→下车站→核对选择保存，保留方向及真实站序校验；采集设置独立保存，星期+选择式起止时间，支持跨午夜及24:00。天气：地点列表→编辑单个→明确统一保存，手输备用、同名行政区、原授权额度。驾驶：目的地列表→独立编辑起终点/时间/启用，搜索目标明确，时间选择替代手填须保持精度与语义。待办/海报：列表→编辑/历史、预览按需；危险操作不挤在主要动作旁。排餐：日期/餐次→分类/搜索→点菜，已选数量与清单始终易达；已确认单菜即时保存，不另设误导性的全局保存；前台2秒同步不变，更新选中状态而不重建正在输入的控件，不抢焦点、不跳滚动位置；未确认写入时保留明确状态与回读。菜品库：分类+搜索+批量选择移至其他分类，保留历史菜单快照。
- 设计候选不扩大系统权限、备份/更新、诊断功能范围；现有功能可集中入口但不把未实现功能冒充可用。

## 精简原型（2026-11-26，待确认）
用户要求继续但不要复杂化。首轮只保留六种通用界面元素：信息行、分隔线、关键数字、导航列表、表单字段及按钮/状态反馈；无需单独的组件库工程、设计系统服务、新框架或生产测试入口。
- 综合展示预览：480×640 CSS px（3:4假设，非实机视口），白底4px边距；顶部日期时间及唯一设置；公交左半、当前天气右半；下方两张地图各自一行（左60%地图，右40%三条路线耗时），再按日期排列菜单、待办；不增加模块大标题。海报暂不放入总览，但独立功能保留；第三个目的地功能不删除，超过两张地图时如何展开仍需确认。地图为完全虚构线条，正式地图须保留真实供应商原图及归因，不据此批准地图裁切/拉伸。现有天气完整详情、轮播、采集、公交方向、数据与权限不变。越狱与未越狱共用内容布局，实际浏览器占用区域、字体与刷新能力待实机验证。
- 手机设置：390px示意，单列整行导航→模块详情，48px以上常用点击区域；电脑：同一设置内容，约210px侧栏；菜单点选、公交搜索/方向/站点及保存反馈做轻量交互示意。其余编辑字段为占位设计，不替代现有完整业务表单；不承诺已完成所有交互或正式无障碍审计。
- 本轮单文件离线 HTML 原型及三张截图在对话交付，使用虚构数据、无联网/存储/依赖；未部署至 NAS，未纳入生产入口。原型在本地 Chromium 通过 set_content 加载，480×640看板尺寸已测得；320/390/768/1440窗口三个模式无横向溢出，导航、演示保存、点菜检查通过，无页面JS异常。首次 file:// 载入被环境管理策略阻止，改内存加载成功；不等于真实手机、旧 Kindle WebKit、NAS持久化或多人同步测试通过。

### 设置交互优化候选
天气/驾驶设置从统一列表进入独立编辑面板（手机单列、宽桌面保留侧栏），保留原接口、权限与显式保存；返回前比较已读取/已保存的配置快照，未保存编辑需要确认，读写进行中禁用相关输入和按钮。保存反馈放在按钮后，失败保留输入；初次读取错误在详情顶部显示并可重试。驾驶目的地使用三个以内选择按钮，仅展示当前组的表单，切换保留其余草稿，校验失败自动展开对应组，搜索反馈在目标组内。统一设置入口采用整行点击；家庭管理的二级导航在手机端紧凑双列，避免六个长入口把内容推到屏幕下方。仍不引入框架、额外持久存储或上游采集；未改变驾驶时段输入语义。本轮增加真实浏览器导航、取消离开、重读和驾驶分组回归，等待 CI；真机适配未验证。

补充：退出/鉴权失效清理时恢复表单禁用状态，海报停留时间立即按新间隔重新排程；真实 Chromium 增加总览两张地图、第三目的地详情入口与无横向溢出的检查。只做这些低风险修正，不扩展测试页面或业务能力。

## 电脑端管理工作台（三栏交互式预览，2026-11-27 用户确认）
- 电脑后台采用固定左侧全局导航 + 中间当前模块设置 + 右侧 Kindle 实时预览。桌面宽屏充分使用可用宽度；左侧约220–250px，右侧预览约390–520px，中间自适应。中间设置区独立滚动，右侧预览固定在视口旁；窗口窄到无法保证表单可用时，预览移至设置区下方。移动端后台与 Kindle 展示页面不随本次架构重构。
- 桌面导航保留首页、公交、天气、驾驶、家庭、系统六个入口；取消独立“显示设置”入口。海报轮播设置直接位于海报管理，本周菜单/菜单显示范围直接位于菜单管理。公交、天气、驾驶的显示行为和更新时间相关设置归属各自模块。预览尺寸、外框和缩放是电脑端辅助工具，不作为设备业务设置。旧 /admin/display 仅兼容跳转到 /admin/family#posters；手机 /home 的显示设置入口保持不变。
- 右侧预览始终复用 /preview 的 display.html/js、既有 API 和 NAS 缓存，不复制一套“模拟展示”HTML。默认跟随当前管理模块/家庭二级标签，可手动锁定查看其他模块；从设置区切换模块时预览同步切换，保存成功后通过同源消息触发一次局域网读取。不得因输入每个字符重复调用供应商，不改变上游请求频率、缓存、限额或后台采集任务。
- 预览仍使用独立 iframe CSS 视口，默认480×640仅为示例，不代表 Kindle 实测分辨率。黑色设备外框、底部标识、灰阶/滤镜仅作用于外框或整个 iframe 的等比缩放；iframe 自身宽高保持用户输入值，不能因外框改变字体、行宽或页面比例。支持适应区域、网页 CSS 1:1、外观开关及恢复默认。恢复默认只重置电脑预览控件，不修改 NAS 配置。
- 预览支持现有展示页面的交互：导航/分区、设置面板、滚动、海报轮播及在已授权时完成待办。待办完成是真实家庭数据写入，沿用现有二次确认和服务端权限；不是“沙盒演示”。预览中的页面切换只改变 iframe 内的虚拟页面，不改变实体 Kindle 当前显示页、设备会话或自动分时状态。其他业务写入仍由原服务端权限、校验和确认决定。
- 交互授权通过同源 postMessage 传递当前页面已经验证的会话令牌；不放入 URL、HTML 文本、DOM 属性、local/session storage 或服务端新状态。子页面只接受来自同源父窗口的消息；只有获得有效令牌后才开放对应交互，服务端原有鉴权仍为最终权限边界。未获得管理权限时仍按现有只读规则显示，不因预览绕过权限。只有专用 /preview 文档允许同源嵌入，所有其他管理页/API继续禁止被框架嵌入；Host/Origin/IP/访客网段限制不放宽。
- 不增加框架、常驻服务、数据库、依赖、WebSocket、浏览器自动化进程或外部供应商请求。每个管理页仅有一个已存在展示页面实例作为预览；其局域网读取沿用原页面节奏，隐藏浏览器标签时按既有逻辑停止/减慢更新。浏览器端多一个 iframe 会增加少量客户端内存/CPU，NAS 资源增量应以 Docker/Chromium 实测为准，不预先宣称为零。
- 电脑后台页面保持简洁：模块标题、真实业务表单、必要保存/错误/权限提示；删除重复开发说明和没有操作价值的状态文案。预览区域常驻但不重复展示接口来源、技术解释或无操作价值的尺寸说明。
- 自动回归：桌面宽屏三栏及右侧固定、窄屏降级布局、六模块预览模式、自动跟随/手动锁定、旧路由跳转、CSS视口/外框等比、预览同源认证握手、token不进入URL/存储、未授权只读、授权后现有交互、保存后预览刷新、手机入口与原 API/采集/配置兼容。真机屏幕比例、物理字体、墨水灰阶/残影、休眠与真实 NAS 资源仍需现场验收；480×640 不作为实机校准结论。
