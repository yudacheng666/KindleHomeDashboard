## 统一版式
- 竖屏白底、4px页边距；日期、时间、设置与紧凑天气摘要同处顶部区域（左侧日期/星期、下一行时刻，右侧天气温度/现象及体感湿度，设置按钮在最右；不显示地点标题，保留轮播及带地点的预警）。公交全宽、首车/次车左右并排。公交在总览仅显示线路、乘车方向、首车/次车状态、计划/预计时刻及有意义的剩余站数/距离；不重复显示“最近一辆/下一辆”“发车计划”“本站到站时间未知”等说明。状态异常时保留简短提示，更新时间只显示时分；独立公交页的完整信息不变。
- 前两个目的地改为左右并排卡片，每张地图保持原图比例和完整范围，地图展示框高140px；目的地名称自然换行、不预留第二行高度，路线摘要放在地图下方，每条路线一行，编号/耗时/距离分列对齐，最快路线加粗。更新时间/异常状态压缩为一行；超过两个目的地时只显示“另 N 个目的地”入口；不足三个时无额外链接，完整驾驶页仍由设置进入。窄屏手机（≤420px）改为上下卡片，避免地图和路线字挤得不可读；600px Kindle 竖屏保持左右两张地图。
- 下方菜单和待办分别分组，菜单按日期、餐次组织，今日无排餐不显示今日空分组；待办按日期组织；两组之间使用清晰分隔，不增加重复大标题。保留既有展示范围、最多三条待办和完成按钮。海报独立显示。
- 字体重新分级：日期/地点/菜单主信息约19–20px，公交状态与路线摘要18–21px，更新时间等辅助信息至少16px；组内行距和间距收紧，组间保留分隔。不得通过整体缩小字体换取空间。删除应用额外添加的地图来源说明；不改变原始地图图片内容。
- 可点击必要标签进入既有详情；保留完整驾驶详情、自动分时、业务缓存、权限和设置。布局按600×800、480×640预览及320px窄屏回归，真实Kindle仍须现场验收。
- 公交保留双车同结构、首车突出、站点方向、真实ETA/首站计划区分、90秒失效和NAS时钟；天气仅显示当前实况与可用湿度/体感，不显示单独观测时间、不显示网页添加的供应商名称、链接或署名文字及所有地点有效预警；完整六项仍在独立天气页，平等地点120秒轮播。
- 地图保持供应商原图及原600×360请求参数，等比缩放，不裁切、拉伸或隐藏归因；PR #25 的600×200全景请求暂不采用，可能改变完整驾驶详情和真实路线可读性，实机确认后才考虑。
- 菜单今日及既有菜单展示范围内的明日摘要，尊重用户配置的自然周/滚动/自定义范围，未取得的范围不显示为没有排餐；完整菜单保留。待办前三项及完整入口，日期分组、仅当期/逾期授权用户可二次确认完成；不改历史与未来任务规则。
- 根路径 / 默认总览；/display#overview 明确入口，/display 既有手动模块和海报恢复逻辑、/auto 自动分时与旧详情/设置返回路径保留。两种 Kindle 使用方式共享内容布局。用户此前批准的独立模块和业务行为不删除。

- 复用 #24 的现有四类只读局域网缓存 API、ES5/XHR、独立刷新和错误降级；公交15秒、其他30秒、天气轮播120秒。未采用 #25 的聚合 API（会新增后端及权限测试范围、15秒重复传输地图），无后端、采集频率、数据库、权限、地图供应商参数变更。若实际网络负载出现问题再测量后考虑聚合/差量；综合页相比单模块增加局域网读取，不能声称零额外负载。
