## 用户目标与必须保留的能力

用户要求公交、天气、驾驶、待办、菜单和海报在同一 Kindle 竖屏网页中综合展示，减少频繁切换。此前已确认「信息页面只保留一个统一设置入口」；待办完成是唯一日常业务写入例外，必须二次确认。保留天气最多三地点平等采集与120秒页面轮播语义、公交最近/后续两车、驾车三个独立目的地且每个目的地有多条备选路线和真实地图的详情、家庭未来待办、菜单可选展示周期、海报大字轮播。

“一页总览”是单一入口页面，不等于把全部模块的所有细节塞进一个物理屏幕。屏幕尺寸与浏览器CSS视口未核实，不能承诺旧 Kindle 无滚动。

## 推荐分区（从上到下；仅示意，不代表上线）

1. 顶部细条：日期、NAS基准时间、唯一「设置」入口。不得使用未经校准的 Kindle 本地时钟冒充权威时间。
2. 天气摘要：当前轮播地点的自定义名称与页码，天气/温度/降雨风险/预警缩写；沿用地点平等和120秒切换，不将两地并列挤在一行，地点切换不请求供应商数据。完整六项与曲线在天气详情保留。
3. 公交摘要：当前选定乘车线路，最近一辆大字号 ETA 或明确状态，第二辆较小字号，计划发车和本站 ETA 必须区分，保留采集时效；避免信息拥挤及零站数误判。完整站点与状态可看公交详情。
4. 驾驶摘要：固定三个目的地行，每行显示目的地匿名自定义名、最快路线突出、三条备选的**真实算路耗时**（仅返回几条就展示几条）、更新时间/失败状态；三张真实地图及拥堵路线的详细比较放在对应目的地详情页，**不在总览强塞三张地图**。驾驶 PR #22 尚未合并；未配置或未上线时显示明确未启用或隐藏卡片，绝不造时间。
5. 待办摘要：逾期、今日、未来的前2–3件未完成任务，日期分组，超出数量给出“另有N件”；仅当期且有完成权限的任务有低调「完成」按钮，确认成功后隐藏，未来不可提前完成。详情页继续显示完整清单与历史入口（历史管理仅设置）。
6. 菜单摘要：今日主要餐次和可选明日预览；日期只显示一次。用户配置的完整自然周/今日起7天/自定义1–31天展示范围在菜单详情页继续生效，总览摘要不修改排餐范围或多人同步规则。
7. 海报摘要：保留2–3行高对比大字提醒，同一小区域内轮播；可进入海报大字详情页看完整内容。不因未来待办自动把未到期海报提前触发。
8. 小字脚注：关键模块的上次更新时间/过期标记，不铺满全屏的技术说明。

## 交互及布局决策候选

- 默认入口由「单一模块」调整为总览；卡片标题或区域点击进入现有只读详情，返回总览，设置仍为唯一统一**管理**入口。此变更涉及现有顶栏标签与自动分时展示模式，属于待批准的关键界面变动，不应在批准前实施。
- 自动分时不再整页替换内容的建议：所有卡片位置固定，通勤时突出交通卡片，其他时段保持可见而弱化；是否替代原自动切换需用户确认。保留目前逻辑直到批准。
- 灰阶高对比、少边框、无装饰图标；公交 ETA 和关键预警优先保证字号。尽量 CSS 表格布局、ES5、XHR，支持老浏览器；长文本自然折行，不截断关键警告。
- 优先在目标设备试排约 320–360 CSS 像素宽；高度不足时保留一个可纵向滚动的完整网页，而非挤压至不可读。禁止假设设备型号或真实视口。
- 总览仅消费 NAS 已采集的缓存，不因同时展示多个模块而提升公交/天气/驾车的上游请求频率或配额，卡片独立按数据变化局部更新，不强制整页刷新。天气与海报独立轮播不牵动其他模块。
- 家庭编辑维持手机设置端、前台同步机制；总览不新增常驻线程、外部账号、地图实时浏览器服务或高权限管理入口。
- 上游故障时，卡片局部标明暂无/过期，其他卡片照常显示；禁用模块可收起成一行，不把未知数据伪装成零或可用。

## 待确认与验收重点

1. 是否采用「总览默认 + 点卡片进详情」，取代首页五个横向模块标签。
2. 驾驶总览仅比较三目的地及其备选路线耗时，**每目的地真实地图在详情页**；不在综合页嵌入三张地图。
3. 自动分时是否从「整页切换」调整为「固定分区，改变强调程度」。
4. 总览优先尽量一屏，但设备尺寸不足可纵向滚动；如用户严格要求零滚动，则必须减少显示条目。
5. 海报摘要保留大字但不能兼容任意长度全文同时展示；需要完整海报时进详情。
