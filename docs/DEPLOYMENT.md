# Docker 本机集成部署原型（未发布）

默认 compose.yaml 只供隔离测试：服务仍绑定容器内部 127.0.0.1:8080，不发布端口、不使用 host 网络，手机和 Kindle 暂不能直接连接。不要把端口转发到局域网或公网，也不要关闭安全校验。极空间 Docker/Compose 版本、CPU 架构、数据卷权限、家庭直连及真正的 NAS 资源占用仍待验收。

## 结构与运行

- 单容器，Python 3.12 slim Debian Bookworm，含时区及 CA 证书；无 pip 运行依赖、浏览器或外部数据库服务。
- 容器 UID/GID 10001；只读根文件系统、无额外 capabilities、禁止提升权限，初始上限 128MiB/0.5 CPU/32 PID。不是实测值。
- `compose.yaml` 需要 Compose v2 支持 bind.create_host_path；指定已经存在的私有目录与令牌环境文件。只默认启用家庭功能，公交联网默认关闭。
- 镜像构建仅包含 dashboard 运行源文件；真实数据、备份、凭证和部署参数放在仓库及构建上下文之外。
- `restart: unless-stopped` 在 Docker 服务正常启动且容器未被手动停止时可自动恢复。健康检查只确认本机静态 HTTP 页面响应，不证明数据源正常，不会自行重启不健康容器。
- SIGTERM/SIGINT 触发正常停止及后台采集退出；长时间异常上游或磁盘操作仍可能超过停止限时。

## 隔离测试操作（技术维护用，不要求普通用户现在执行）

在专用测试机上准备绝对路径的私有空目录，令 UID/GID 10001 具备读写权限，目录权限尽量为0700。不要对已有 NAS 共享目录递归改所有权。另准备仓库外0600环境文件，用本机密码学随机数分别生成独立的 KHD_READ_TOKEN / KHD_ADMIN_TOKEN（32字节随机数的 URL-safe 编码即可）；禁止公开、粘贴到聊天或 CI，不使用默认口令。Docker 管理员可读取容器环境，勿向他人共享 inspect/config 输出。

将 KHD_DATA_DIR、KHD_PRIVATE_ENV 指向上述绝对路径。执行 `docker compose config --quiet`、`docker compose build`、`docker compose up -d --no-build`。使用容器内部本机 HTTP 检查，不映射端口。健康检查、容器状态和停止操作可通过 Docker 管理器查看。停止使用 `docker compose stop`；不要删除数据目录。

## 升级与恢复

正式发布前需固定镜像版本及 digest，保留上一已验证镜像，备份数据库及独立的私有启动配置/令牌。停止服务后用 `dashboard.backup` 备份，检查返回结果；更新镜像时保留私有目录映射，若版本不兼容先在新目录恢复并验证。禁止自动回滚旧数据库结构或旧访问限制。恢复强制阻断公交联网，尚无受审查的重新启用入口。详见 TEST_PLAN.md。当前原型镜像标签 dev 不代表正式版本。

## 验收

`tests/docker_smoke.sh` 只用于隔离 Linux CI（需要 Docker Compose 和 sudo），生成虚构数据及临时令牌，不使用家庭网络。检查真实构建、非 root、资源限制、无端口映射、HTTP 鉴权、正常停止、删除并重建容器后的持久数据、镜像不含 Git/测试目录。采样资源不代表实际通勤负载或 NAS 兼容性。不得将真实数据导入测试。正式部署必须通过真实局域网、防火墙、设备及 NAS 独立验收。

## 家庭局域网直连（用户确认简化方向，未正式部署）

配对功能已移除。日常家庭使用不要求注册设备、输入只读令牌或维护证书。保留默认回环鉴权模式及可选 HTTPS；另提供独立 `compose.lan.yaml`（不要与默认 compose 合并）。私有配置指定 `KHD_LAN_HOST` 为 NAS 的固定私有 IPv4 地址，`KHD_LAN_NETWORK` 为可信家庭子网 CIDR，`KHD_DATA_DIR` 为仓库外数据目录。使用 `docker compose -f compose.lan.yaml config --quiet` 检查，待真实网络验收后才启动。手机/Kindle 浏览器访问该 NAS 地址的8080端口，/display 手动展示、/auto 自动分时展示、/home 家庭管理、/ 公交设置，无需配对或登录。默认开启家庭功能；公交联网需显式开启并指定采集窗口，见下节。该模式显式 --open-admin，任何获准网段内可连接设备都可查看、修改及删除内容（仍有删除确认）。HTTP 不加密，不适用于不可信网络；禁止公网转发、访客网络访问、反向代理及其他会隐藏来源地址的中转。NAS 防火墙及路由器必须限制可信家庭网络，不能仅依赖 Docker 端口绑定；核查 Docker 转发规则及源地址保留，若 NAT 改写来源或实际网段不符合则不启用。服务器仅接受配置的 RFC1918 子网真实来源、精确 Host/Origin，不信任代理头。容器内监听 IPv4，宿主机发布仅指定私有地址。若需管理凭证，手动配置 --tls-cert/--tls-key 与 KHD_ADMIN_TOKEN，不使用 --open-admin；客户端必须验证证书；此可选配置尚无专门 Compose 模板。默认 LAN Compose 不使用凭证且停用旧回环健康检查，后续可补充适配的健康检查。通过默认 Compose 可回到原回环鉴权模式，不迁移业务数据库。普通用户无需现在执行命令，待 NAS/Kindle 可用后进行安装说明及现场验收。

## 自动分时显示（可选原型）

沿用私有启动参数中明确设置的公交采集窗口（NAS 配置时区、星期、开始/结束时间，支持跨午夜），不另设定时服务或真实通勤默认值。/auto 打开后自动选择：窗口内公交有配置且未禁用时显示公交，包括等待/过期/受限等真实状态；其余时间显示家庭，如家庭未启用则保留公交状态页。/display 默认手动，点击自动分时开启；手动选择模块（含同模块）、前后翻页、暂停轮播或进入轮播设置时退出分时，点击自动分时恢复。原家庭轮播启停及停留设置独立生效，不自动开启轮播。/auto 可作为设备收藏地址，重新打开自动恢复分时，手动覆盖不跨重启保存。按当前模块15/30秒读一次 NAS 本地自动展示接口，不调用公交上游，不改变采集频率；后台标签暂停，失败隐藏内容、恢复重读。未实现独立夜间休眠、置顶海报跨模块抢占或自动时段手机编辑；这些规则及正式布局待确认。Kindle 屏保/休眠下浏览器是否持续运行须实测。

## 首次安装准备清单（待现场验收，不是已发布安装包）

1. 在 NAS 上确认 Docker/Compose 可用、架构与镜像匹配，准备独立空的私有数据目录（UID/GID 10001 可读写）；原 HA 数据及共享目录保持不动。确认 NAS 固定私有 IPv4、可信家庭子网和防火墙，仅在家庭局域网测试。
2. 将私有配置文件放在仓库外，权限0600。以下是字段说明，不是可直接使用的真实配置：
   - KHD_DATA_DIR：私有数据目录绝对路径。
   - KHD_LAN_HOST、KHD_LAN_NETWORK：NAS 私有 IPv4 地址及可信家庭子网 CIDR。
   - KHD_BUS_ENABLED：默认0，明确准备好后改为1。
   - KHD_BUS_WINDOWS：公交采集窗口，星期0=周一、6=周日；格式 DAYS:HH:MM-HH:MM，多星期用逗号，多窗口用分号；可跨午夜。无默认通勤时间。启用公交时不能为空，最多32个窗口。
   - KHD_TIMEZONE：默认 Asia/Shanghai，可按所在地选择 IANA 时区。
   - KHD_BUS_DAILY_LIMIT：本地每日请求上限，1至1000（默认1000），不代表供应商授权或免费额度。
3. 使用 `docker compose --env-file <私有配置文件绝对路径> -f compose.lan.yaml config --quiet` 检查 Compose（不能检查所有应用级参数），再在获准的 NAS 上构建、启动。错误的应用参数会拒绝启动，不应打印实际私有时段。CLI --window 和环境窗口不可混用；修改本地环境文件后重建容器使其生效，不删除数据目录。保持不公开私有配置、docker inspect/config 完整输出。
4. 家庭功能先验收：手机直接访问 NAS 的8080端口及 /home，添加虚构待办/海报/菜单，在 /display 核对显示和轮播；再确认 /auto 行为。测试其他网段、访客网络不得访问。
5. 公交启用后，在 / 选择线路、方向和上下车站，保存后确认真实预计到站；对照现场车辆到站，确认代表性通勤时段、第二辆车、网络失败/过期提示、非采集时段及夜间。供应商拒绝或收费时停止，不绕过限制。
6. Kindle 先核实型号及固件，直接试用浏览器 /auto，检查字体、触摸、长海报、休眠、恢复、刷新和耗电；无需先越狱。实际不兼容再评估客户端方案，不擅自降级固件。最后核查 NAS CPU/内存、HA 不受影响、容器重建/数据保留及备份恢复。普通用户实际安装前还需准备适配其 NAS 的操作指引。
7. 备份恢复后的公交安全阻断与供应商拒绝目前共用同一持久字段，不能根据现有状态区分。不要手动清空预算数据库或解除阻断；恢复后先使用家庭功能，保留原数据和备份。需查明限制来源并确认允许访问后再设计明确审查的恢复流程，暂不提供解除命令。

目前尚无正式镜像、未合并发布；上述步骤在真实家庭环境全部完成前不能声称已上线。

## 镜像发布安装及更新（首版候选）

发布准备：VERSION 指定 v0.1.0-rc.1，主分支版本文件变更或主分支手动运行 Publish tested Docker release 工作流才允许发布。先检查公开路径、Python、网页、Chromium 和密钥扫描，再用免费 amd64/arm64 标准运行器分别构建并执行 Docker 冒烟测试，发布已测试的镜像，合成多架构清单，GitHub Release 写入固定摘要及独立 compose.release.yaml。候选包仍未实机验收，不称稳定版。首次 GHCR 包默认私有，所有者核查仅公开源代码镜像后设为 public，匿名拉取；未经确认不使用付费服务。基础镜像构建标签仍未锁定，最终产物用摘要固定。工作流执行与镜像公开拉取均待验证。

一次性下载 Release 内的 compose.release.yaml（不要与其他 Compose 文件叠加），沿用前述私有目录、环境变量、权限及网络检查。在仓库外私有环境文件添加 KHD_IMAGE=发布说明中的完整 ghcr.io/...@sha256:... 引用。执行 docker compose --env-file <私有文件> -f compose.release.yaml config --quiet，随后 pull，再 up -d --no-build。无需源码或本机镜像构建。极空间界面及 Compose 支持尚未实测。无镜像可拉取时不要宣称已发布安装包。

后续更新只修改本地 KHD_IMAGE 为下一已核验发布摘要，不重复下载源码或 Compose（除非发布说明明确部署参数迁移）。先保留旧镜像及私有配置，停止服务并完成离线备份，检查备份后拉取新镜像并重建，保留数据挂载。升级失败时仅在确认数据库兼容的情况下回退旧镜像；不直接覆盖数据库、不解除公交访问阻断。软件内检查更新和用户确认后安装是后续目标，尚未实现；不挂载 Docker socket、不开放 NAS 管理权限、不新增常驻更新器。网页可先实现只读版本检查，安装由 NAS 端受控操作完成，具体方式待现场环境确认。
